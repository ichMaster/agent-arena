# AgentArena — Branch Comparison Report 📊

**Date:** 2026-07-21 · **Scope:** all 7 dev branches (everything except `main`)
**Method:** each branch was independently reviewed **read-only** (via `git show` — no checkouts) by a
dedicated review pass covering inventory, architecture adherence, correctness, typing, testing, and
security; speed data comes from each branch's own statistics/report files (or git timestamps where no
file exists); post-generation bugs from each branch's `post-code-generation-errors.md` (absence = no
post-generation bugs, per the comparison requirements). User marks are folded in as a separate
dimension — they measure developer experience, not code internals.

**Branch naming convention:** `<Model set>-<Spec model>-<Code model>-dev`. Branches without a
code-generation model (`Anthropic-Opus4.8-dev`, `Gemini-3.1Pro-dev`) were built **interactively** —
step by step with manual testing after each version — and are **evaluated separately** from the five
autonomous-pipeline branches.

**How to read the model pairs:** `Spec model → Code model` — the model **before** the arrow authored
the specification set (game specification, architecture, roadmap, web-UI spec); the model **after**
the arrow generated the entire implementation from that spec. So `Claude Opus 4.8 → Claude Sonnet 5`
= *spec written by Opus 4.8, code generated by Sonnet 5*. The quadrant's short names follow the same
pair: `Opus-Sonnet` = Opus-authored spec + Sonnet-generated code, `Pro-Flash` = Gemini 3.1
Pro-authored spec + Gemini 3.5 Flash-generated code.

**Three headline findings:**

1. **The spec is the strongest predictor of quality.** All three branches built from the Claude Opus
   4.8-authored spec (1,171 lines, concrete wire contracts, an identity model, security §, testing §)
   scored ≥ 9.0 architecture adherence. All four branches built from the Google Gemini 3.1 Pro-authored
   spec (~406 lines, no wire schemas, no seat-identity rules) shipped identity-model defects — except
   where Claude Sonnet 5 invented the missing contracts itself (and even then it introduced 2 Critical
   seat bugs that its review pass had to catch).
2. **The code generator matters as much on a weak spec.** On the *same* Google Gemini 3.1 Pro spec:
   Claude Sonnet 5 → 7.75, Google Gemini 3.5 Flash → 5.25, Google Gemini 3.1 Pro → 3.5. On the strong
   Claude Opus 4.8 spec, Claude Opus 4.8 and Claude Sonnet 5 both landed 9.0+.
3. **Speed and quality traded off hard — nobody got both.** The Magic Quadrant's Leaders box is
   empty: the high-quality builds all took 1h 16m+, and the fast builds (14–35 min, 2–8× faster)
   paid in live-debug time and shipped defects (one shipped with 42% of its tests failing). Within
   the quality tier, Claude Opus 4.8 → Claude Opus 4.8 was 26% faster than Claude Opus 4.8 → Claude
   Sonnet 5 at essentially equal quality — but Sonnet 5's zero-escape record wins the adjusted
   overall (§10).

## 2. Detailed Code Review — per branch

> Full unabridged review documents live in [`code-reviews/`](code-reviews/) — one file per branch
> (inventory, file-level findings, spec/speed/bug extracts, and scoring rationale). The sections
> below are the condensed versions.

### 2.1 `Anthropic-Opus4.8-Opus4.8-dev` (spec: Claude Opus 4.8 · code: Claude Opus 4.8) — 🥈 pipeline (adjusted §10); fastest of the high-quality builds

- **Size:** 1,198 Python LOC (19 files) + 534 web LOC; 174 test functions → **189 passing**; strict mypy over all 3 packages.
- **Architecture (9.5/10):** both seams pristine (`GameInterface` ABC, `LLMClient` + factory); server re-derives seat/turn/legality per move; state replayed from the move log; `UNIQUE(match_id, symbol)` + token-as-PK identity; observer flag written before any seat can exist. Code cites spec § numbers throughout.
- **Correctness:** `apply_move` never raises (incl. the `bool`-as-`int` trap); `current_turn: null` at terminal; WS cleanup in `finally` with `asyncio.shield`; seat race solved by bounded IntegrityError-retry (tested with a real `asyncio.gather` race); malformed JSON, non-dict JSON **and** binary frames all answered gracefully.
- **Testing (9/10):** contract tests for every seam, full-game WS integration, a genuine agent-vs-agent e2e with exact per-side LLM call counts, README doc-smoke tests, and an **autouse no-paid-call guard with its own meta-test**.
- **Security (8.5/10):** secrets agent-only + fail-fast; prompt-injection guard; server-enforced observer refusals; XSS-safe `textContent` rendering. Residual: token in WS query string, no chat length cap/rate limiting.
- **Weaknesses:** double log-replay per turn (deferred LOW), `window.prompt` UX, the one live-testing escape (stdout buffering, below).

### 2.2 `Anthropic-Opus4.8-Sonet5-dev` (spec: Claude Opus 4.8 · code: Claude Sonnet 5) — 🥇 pipeline (adjusted §10), highest quality

- **Size:** 1,185 Python LOC + 684 web LOC; 192 test functions → **226 passing** (largest suite of all branches); strict mypy clean.
- **Architecture (10/10):** textbook implementation of every spec non-negotiable; identical seam discipline to 2.1 plus slightly deeper test coverage of the identity model.
- **Correctness:** same strengths as 2.1 (shielded cleanup, seat-race retry, three-layer malformed-frame handling). Minor: a theoretical TOCTOU on turn-check-then-log (mitigated by per-connection sequential handling + SQLite's single writer); agent-side `json.loads` unguarded against a malformed *server* frame.
- **Testing (9/10):** 226 tests incl. agent-vs-agent e2e, contract tests, doc-smoke, autouse paid-call guard + meta-test.
- **Security (9/10):** best-in-class of the seven; same residuals (query-string token, chat length).
- **Distinction:** the **only pipeline branch with zero post-generation bugs** — no `post-code-generation-errors.md` exists; both HIGHs (seat race, undeclared `uvicorn`) were caught in-pipeline.

### 2.3 `Anthropic-Gemini3.1Pro-Sonet5-dev` (spec: Gemini 3.1 Pro · code: Sonnet 5) — 🥉 pipeline

- **Size:** 1,005 Python LOC + 684 web LOC; **130 test functions → 147 passing** at a 1.8:1 test:source LOC ratio; `mypy strict` only on `games/` (weakest typing enforcement of the Anthropic set).
- **Architecture (8/10):** clean seams, true server authority, token-keyed seats **despite the spec not specifying them** — Sonnet 5 invented the missing contracts. But the spec's crash-rehydration promise is unimplemented (moves are logged, never replayed; a restart loses live games), and the spec's own module tree never matched the build.
- **Testing (9/10):** a highlight — full games over TestClient WS *and* over a **real uvicorn server on a thread**; proven-fail-then-pass regression tests; LLM always mocked.
- **Security (6/10):** Pydantic-validated payloads, 4001 on bad tokens, XSS-safe DOM; but CORS `*` **with credentials**, unexpiring query-string tokens, a disconnect seat-takeover window, and a suspicious **`httpx2==2.7.0`** dependency (see §8).
- **In-pipeline review caught 12/12 findings (2 Critical — seats keyed by *name*, no seat reclaim), all fixed in a 16m 43s pass.** 6 live bugs still surfaced afterwards (below).

### 2.4 `Gemini-3.1Pro-3.5Flash-dev` (spec: Gemini 3.1 Pro · code: Gemini 3.5 Flash) — 4th

- **Size:** 818 Python LOC + 784 static-web LOC; 25 tests (real-uvicorn integration is genuinely good); two-tier typing (server would not pass the strict mypy the stats file claims).
- **Architecture (5/10):** game seam + server-side move validation honored; **LLM seam not swappable** (hardcoded `GeminiClient`); **token auth is format-theater** (any self-minted UUID connects; connection-order fallback seating; client-asserted symbols); `repo.log_move` dead code — **no move persistence at all**, spec §4 rehydration unimplemented.
- **Security (4/10):** live `innerHTML` XSS in chat (LLM output executes in every spectator's browser), spoofable sender, CORS `*` + credentials.
- **Speed is its story:** 35m 26s for all 15 phases — but it then **failed its first real run in 8 distinct ways** (2 module-path, 2 database-init/FK, 2 WS lifecycle, 1 seat-stealing, 1 LLM hang), several demo-blocking.

### 2.5 `Gemini-3.1Pro-3.1Pro-dev` (spec: Gemini 3.1 Pro · code: Gemini 3.1 Pro) — 5th

- **Size:** 616 Python LOC + 639 frontend LOC; 19 tests, **8 failing at HEAD** (a final untested hot-fix flipped the engine's default turn and never updated the tests).
- **Architecture (4/10):** engine + re-validation are real, but the DB is **dead code in the live path** (nothing persisted during gameplay), tokens are an unbound global set, seats are keyed by the WebSocket object, and — worst — a **`first_move` query param lets any connecting client mutate `game.current_turn` mid-game**, breaking server authority outright.
- **Security (3/10):** `innerHTML` XSS from LLM chat, client-mutable turn order, no `finally` cleanup (socket leaks), one dead socket aborts a broadcast for everyone.
- **Process:** 26 commits for 34 issues (2–4 issues per commit — untraceable); 9 post-gen incidents rewrote ~16% of the codebase in one commit that also introduced the test regression. `errors.md` and `post-code-generation-errors.md` coexist in root and disagree on counts.
- **Speed is extraordinary (13m 37s)** — and it is exactly what the quality data says it is.

### 2.6 `Anthropic-Opus4.8-dev` (interactive, Opus 4.8) — 🥇 interactive

- **Size:** 1,279 Python LOC + 679 web LOC; 192 test functions → **235 passing** (the largest final count); strict mypy; 18 release tags (15 phases + 3 patch releases).
- Same architectural DNA as 2.1/2.2 (it authored the spec the Anthropic branches share): clean seams, replay-derived state, token-keyed seats, shielded cleanup, injection guard, mechanically-enforced no-paid-call rule.
- **~30 review findings over the build (1 HIGH — the seat race; 5 MEDIUM), every one tracked to a status in per-phase review docs**; the patch releases (v02.03.01/.02 hardening, v05.03.01 packaging) reflect real post-release fixes — the honest cost of being the *first* build to discover each pitfall interactively.
- Scores: 9 / 10 / 9 / 8 → **9.0**.

### 2.7 `Gemini-3.1Pro-dev` (interactive, Gemini 3.1 Pro) — 🥈 interactive

- **Size:** 720 Python LOC + 744 web LOC; 21 tests (engine coverage good, **zero client/LLM tests**), 1 stale failing test at HEAD.
- **Identity model fails the shared requirements:** join tokens are minted but **never stored or checked**; seats assigned by connection order (an early spectator steals a player seat — "fixed" only by launch-order docs); X-drop-reconnect can create **two O seats**. No move persistence (`log_move` never called); UI hardcodes the human as X, so the README's two-tab human-vs-human flow cannot work.
- **Security:** stored XSS via `innerHTML` chat; spoofable sender; CORS `*` + credentials. Root-level workspace debris committed (`agent_out.txt`, `match.txt`, `test_client.html`).
- Scores: 6 / 4 / 5 / 3 → **4.5**. Fast (~5h for all 15 versions) and pleasant to drive (user: 5/5 DX), but the code carries real unresolved defects.

### 3.3 What the reviews converge on

1. **Secrets isolation is the only universal pass** — all seven branches keep the model API key in the
   agent's `.env`, never sent to or logged by the server. The one spec rule every build honored.
2. **The identity model is the sharpest discriminator.** Every Claude-coded branch keyed seats by
   verified token with a DB uniqueness constraint; every Gemini-coded branch shipped some form of
   connection-order or unverified-token seating — including `Pro-Sonnet`'s starting point, where
   only the in-pipeline review (2 Critical findings) pulled it back.
3. **XSS splits perfectly by code generator.** All four Claude-coded UIs render chat via
   `textContent`; all three Gemini-coded UIs inject LLM/chat content via `innerHTML` — a live stored
   XSS in each, unfixed at HEAD.
4. **Persistence-as-designed exists only on the Opus-spec branches.** Replay-from-move-log is real on
   the three Opus-spec builds; on all four Gemini-spec builds the DB layer is either dead code in the
   live path or logs without replaying.
5. **Self-reported stats correlate with review score.** The three Anthropic-pipeline reports were
   verifiable against HEAD; both Gemini-pipeline stats files make claims (green suite, strict mypy)
   their HEAD contradicts.

## 8. Cross-Cutting Observations & Flags

1. **⚠️ `httpx2` dependency (supply-chain flag).** Both `Gemini-3.1Pro-dev` and
   `Anthropic-Gemini3.1Pro-Sonet5-dev` depend on `httpx2` (the latter pins `httpx2==2.7.0` and imports
   it in code). The canonical package is `httpx`. Verify this package's provenance before installing
   these branches; recommend replacing with `httpx`.
2. **`innerHTML` chat rendering is the recurring XSS** — present on all three Gemini-coded UIs, absent
   on all four Anthropic-coded ones (`textContent` throughout). Since chat carries live LLM output,
   this is remotely-triggerable, not theoretical.
3. **CORS `allow_origins=["*"]` + `allow_credentials=True`** appears on three branches — an invalid
   (browser-rejected) but sloppy combination.
4. **Identity is the discriminating requirement.** Every branch got the game engine right; what
   separated the field was seat identity (token-keyed + DB-constrained vs connection-order) and
   state durability (replay-from-log vs in-memory only). A future spec should lead with these.
5. **User-marks vs deep review divergence:** the user scored `Gemini-3.1Pro-dev` "Bugs in code: 5/5 —
   minor fixes"; static review found unresolved seat-stealing, stored XSS, and a failing test at HEAD.
   Both are true from their vantage points — the demo *ran* smoothly (what the user saw), while the
   defects live in paths a happy-path demo doesn't exercise. This gap is itself a finding: **an
   interactive session's perceived quality under-reports latent defects.**

## 10. Final Adjusted Scoring — Code-Review Findings Folded In

**Why adjust:** the original convention ("no `post-code-generation-errors.md` = no bugs") turned out
to under-count once the full reviews landed:

- Two branches carry **unresolved defects at HEAD with no bug file at all** — `Gemini-3.1Pro-dev`
  (seat-stealing patched only in docs, stored XSS, 1 failing test) and `Gemini-3.1Pro-3.1Pro-dev`
  (8 failing tests, client-mutable turn order, XSS, dead DB layer).
- Both Google Gemini pipeline branches' **self-reported stats are contradicted at HEAD** ("19 tests
  passed / mypy 0 issues" vs a red suite; "mypy strict clean" vs an untypeable `server/`).
- Conversely, `Anthropic-Gemini3.1Pro-Sonet5-dev`'s 6 live bugs were **all genuinely fixed with
  regression tests** — a documented-bug count alone over-penalizes it.

The adjusted model therefore replaces the raw bug count with a **Defect outcome** dimension scoring
what actually remains in the shipped code.

**Model:** Overall = Quality composite ×40% + Defect outcome ×20% + Speed ×15% + Spec quality ×15% + User DX ×10%
(Speed banded: pipeline <20m=10, 20–45m=9, 45–90m=8, 90–120m=7; interactive banded separately.
DX = user marks ×2. Spec = lineage score as built-from.)

   one was fixed with a proven-to-fail-then-pass regression test, which is the process working as
   intended given the thinner spec it built from.

## 11. Bottom Line

1. **Best overall artifact (adjusted #1, §10): Claude Opus 4.8 spec → Claude Sonnet 5 pipeline** —
   the only branch with zero escapes and nothing unresolved at HEAD (226 tests); the branch to keep.
2. **Best balance *within the quality tier*: Claude Opus 4.8 spec → Claude Opus 4.8 pipeline** —
   within 0.25 quality points of #1 while 26% faster (the 0.15 adjusted gap is inside scoring
   noise). Honestly, though: at 1h 19m it is still 2–6× slower than the Gemini pipelines — no branch
   earned the quadrant's Leaders box.
3. **Most impressive relative result: Google Gemini 3.1 Pro spec → Claude Sonnet 5** — the generator
   compensated for a thin spec by inventing correct contracts (token seats, structured output) the
   spec never demanded.
4. **Speed Prize ⚡: Google Gemini 3.1 Pro → Google Gemini 3.1 Pro** — 13m 37s for all 15 versions,
   ~6–8× faster than the Anthropic pipelines (runner-up: 3.5 Flash at 35m 26s, the fastest
   green-suite build). But the Gemini pipelines' speed is not backed by verification discipline: a
   red suite and client-mutable turn order (3.1 Pro) or XSS and format-only auth (Flash) remain at
   HEAD — fine for prototypes, not for anything whose identity/persistence semantics matter.
5. **Invest in the spec.** The single highest-leverage artifact in the whole experiment was the
   484-line architecture document: every branch that had it scored ≥ 9 adherence; every branch that
   didn't shipped an identity bug.
