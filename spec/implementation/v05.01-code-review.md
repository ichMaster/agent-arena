## Findings

### #1 🟠 Binary frame not covered by the malformed-message fix (MEDIUM)
**Scenario:** `receive_text()` (verified against the installed Starlette source, not assumed) does
`cast(str, message["text"])`. A **binary** WS frame carries a `"bytes"` key, not `"text"`, so
`message["text"]` raises an uncaught `KeyError` — propagating out of `_ws_connection` exactly like the
pre-fix JSON-decode crash. The app's real clients only send text, but a raw/malformed WS client could
send a binary frame and crash its own connection the same ungraceful way this issue just closed for
bad JSON. **Fix:** wrap `await websocket.receive_text()` itself in a `try/except KeyError` alongside
the existing handling, sending `error_event("malformed message")` and continuing. **Regression test:**
`tests/test_reconnect.py::test_binary_frame_keeps_connection` — `ws.send_bytes(...)` yields the
graceful error and the connection stays usable.

## What's solid
The core JSON handling is correct and adds no new wire shape (reuses `error_event`).

(4/4 repeated runs).
