## v01.03 Tasks

### ARENA-008 — WebSocket Schemas & ConnectionManager

**Description:**
Sets up the foundational structures for WebSocket communication in `server/websockets.py`.

**What needs to be done:**
- Define Pydantic schemas for inbound payloads (`ClientActionPayload`) and outbound events (`ServerPushEvent`).
- Create a `ConnectionManager` singleton class mapping `match_id -> List[WebSocket]`.
- Provide basic manager methods: `connect`, `disconnect`, `broadcast`.

**Dependencies:** None

**Expected result:**
The connection manager and schemas are fully defined and type-checked, ready to be wired into FastAPI endpoints.

**Acceptance criteria:**
- [ ] Pydantic schemas enforce type validation for generic WS payloads.
- [ ] `ConnectionManager` stores and removes WebSocket connections reliably per `match_id`.
- [ ] **Unit test:** Pytest verifies the `ConnectionManager` methods track connection counts correctly.
- [ ] Contributes to DoD: Establishes the data structures needed for bidirectional JSON events.

### ARENA-009 — WebSocket Endpoint & Auth Handshake

**Description:**
Implements the `/ws/match/{match_id}` endpoint in `server/main.py`.

**What needs to be done:**
- Implement the FastAPI `websocket` route.
- Extract the Auth Token from the WebSocket query parameters.
- Validate the Auth Token against the lobby token generator logic (or mock if not persisted) before calling `await websocket.accept()`.

**Dependencies:** ARENA-008

**Expected result:**
A client can attempt to connect to the WebSocket endpoint and will be accepted only with a valid Auth Token.

**Acceptance criteria:**
- [ ] `/ws/match/{match_id}` route is active.
- [ ] Connections without valid tokens are immediately closed.
- [ ] Valid connections are registered in the `ConnectionManager`.
- [ ] **Contract test:** TestClient simulates a WS connection attempt with and without valid token query params.
- [ ] Contributes to DoD: Opens the physical connection channel for clients.

### ARENA-010 — Event Routing & Broadcast Loop

**Description:**
Implements the persistent listen loop for active WebSockets, validating inbound JSON and routing it.

**What needs to be done:**
- Implement an `async for` or `while True` loop listening for `websocket.receive_json()`.
- Wrap the raw JSON in the `ClientActionPayload` schema to validate it.
- Route valid chat payloads to the repository and broadcast them back to the match channel using the `ConnectionManager`.

**Dependencies:** ARENA-009

**Expected result:**
Incoming JSON messages are validated and successfully broadcast to other connected clients in the match.

**Acceptance criteria:**
- [ ] The receive loop continuously handles incoming messages without crashing the server.
- [ ] Invalid JSON or schemas are handled gracefully (e.g. error broadcasted back to the sender).
- [ ] Chat messages are persisted to DB and broadcast to all connected clients.
- [ ] **Unit test:** Ensure `receive_json` correctly passes valid structures to the broadcast method.
- [ ] Contributes to DoD: Closes the loop allowing chat exchange over WS.

### ARENA-011 — Concurrent WebSocket Tests

**Description:**
Validates the stability of the WebSocket architecture against multiple concurrent dummy clients.

**What needs to be done:**
- Write robust `pytest-asyncio` tests utilizing `httpx2`/`starlette` WebSocket test contexts.
- Simulate 2+ clients connecting to the same `match_id`.
- Simulate them simultaneously sending `ClientActionPayload` chats.
- Assert both clients receive the broadcasted `ServerPushEvent` chat messages.

**Dependencies:** ARENA-010

**Expected result:**
Full confidence that the connection manager correctly segregates matches and successfully routes real-time data under concurrency.

**Acceptance criteria:**
- [ ] Tests spawn multiple WS test clients concurrently.
- [ ] Broadcast payloads arrive successfully to all clients in the match.
- [ ] **Integration test:** Simulates end-to-end WebSocket chat session.
- [ ] Meets Phase DoD: Verifies that multiple dummy clients can exchange chat payloads without crashing.
