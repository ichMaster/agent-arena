## Findings

### #1 🟡 Generic opponent label (LOW) — DEFER → v05
`renderPlayers` labels the non-me card "Player X/O" + "Haiku · Agent". **Scenario:** in a human-vs-human
match the opponent is mislabelled "Agent"; and the agent's actual persona name isn't shown. The wire
`joined`/`state_update` payloads carry no participant display names, so this needs a protocol addition
— out of MVP scope (web_ui_spec §10). Homed to v05 polish.

### #2 🟡 Win line from the DOM (LOW) — accepted
`handleGameOver` reads cell `textContent` to find the winning line. It only runs on `game_over`, which
always follows the final `state_update` that rendered those marks, so the DOM is authoritative-enough
for a purely presentational highlight (the server owns the real result). Kept.

## What's solid
The interactivity gate matches §6.2 exactly; `cell.disabled` (attribute, not just class) keeps the
keyboard a11y contract; no optimistic board mutation; the winning line is presentation-only (server
sends just `result`); `resetPlayState` closes the §7 second-match regression; zero model calls.

## Architecture impact
None — presentational rendering; no documented contract changed.
