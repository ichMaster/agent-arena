## Findings

### #1 🟡 Generic opponent label (LOW) — deferred
`renderPlayers` labels the non-me card "Player X/O" + "Haiku · Agent". In a human-vs-human match the
opponent is mislabelled "Agent"; and an agent's persona name (e.g. "Ironclaw") isn't shown either way.
The wire `joined`/`state_update` payloads carry no participant display names, so a faithful label needs
a protocol addition — out of MVP scope (web_ui_spec §10). Homed to **v05 polish**.

## What's solid
The interactivity gate matches §6.2 exactly: a cell is playable only when empty + game active +
`current_turn === mySymbol` + legal, expressed through the real `<button>.disabled` attribute (not just
a class), so the keyboard-a11y contract holds. No optimistic board mutation anywhere — a click sends
`submit_move` and the board re-renders only from the resulting `state_update`, so the server stays the
sole authority. The winning line is derived **presentationally** (from the already-rendered terminal
board — events arrive in order, so it's safe) and never treated as authoritative; `game_over` carries
only `result`. `resetPlayState` closes the §7 second-match regression (no permanently-disabled board).
Zero model calls; nothing rendered via `innerHTML` from untrusted data (only the fixed turn-banner
markup).

## Architecture impact
None — presentational rendering; no documented contract changed (the winning line is client-derived).
