## v04.03 Tasks

### ARENA-030 — Implement Board Reactivity & Gameplay Controls

**Description:**
The UI needs to visibly update the Tic-Tac-Toe grid when `state_update` events are received, and allow the Human player to click cells to send moves when it is their turn.

**What needs to be done:**
- Implement `renderBoard(state)` in `app.js` to iterate over the 9-cell `board` array.
- Update the DOM nodes (`#cell-0` to `#cell-8`) by injecting the 'X' or 'O' text and appending the respective CSS classes (`x` or `o`) to trigger the neon glow.
- Update the Player Cards visually to indicate whose turn it is (`.active`).
- Make empty cells clickable *only* if `current_turn === "X"` and the game is active.
- Wire cell clicks to send a `submit_move` JSON payload over the WebSocket.

**Dependencies:** None

**Expected result:**
The user sees the board update in real-time as the agent moves, and can successfully play their own turns by clicking the grid.

**Acceptance criteria:**
- [ ] Cells display X or O with proper Glassmorphism glow based on server state.
- [ ] Cells are only clickable when it is the human's turn.
- [ ] Clicking an empty cell correctly transmits the move to the server.

### ARENA-031 — Implement Chat Interface & Game Over State

**Description:**
The sidebar chat ledger must become functional, and the game must gracefully handle the end-of-game event.

**What needs to be done:**
- Implement `renderChat(messageData)` to dynamically append new `div.msg.system`, `div.msg.user`, or `div.msg.agent` elements to the `#log` ledger based on the sender.
- Enable the `#chat-input` and `#sendBtn` elements when connected, and wire them up to send `chat_message` payloads over the WebSocket.
- Handle the `game_over` WebSocket event by displaying an alert or updating the UI (e.g. Server Status text) to indicate the winner (X, O, or draw).
- Disable further board clicks when the game is over.

**Dependencies:** None

**Expected result:**
Players can type and send messages to the AI agent, and see the agent's trash-talk appear in the ledger. The game halts properly on a win/loss/draw.

**Acceptance criteria:**
- [ ] `chat_message` payloads are appended to the ledger with correct styling.
- [ ] User can type in the input box and send messages to the server.
- [ ] `game_over` payloads freeze the board and display the winner.
