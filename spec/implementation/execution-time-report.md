## Bugs found and fixed during the run (not pre-existing — surfaced by this run's own validation)

1. **v01.02** — Pinned dependency versions (`pydantic` 2.10.4 et al.) required building `pydantic-core` from source via a Rust toolchain that doesn't support the local Python 3.14 interpreter. Re-pinned to versions with prebuilt `cp314` wheels.
2. **v01.03** — `@app.on_event("startup")` is deprecated, and more importantly a bare `TestClient(app)` never triggers it at all, so the DB schema was silently never created under test. Replaced with a `lifespan` context manager; `/lobby/match` was also never persisting a `MatchModel` row at all, which would have made every chat message fail the FK constraint added in ARENA-007.
3. **v02.03** — A `game_over` broadcast closes every connection in the room server-side, including the sender's own socket mid-loop; the loop then called `receive_json()` again on the now-closed socket, raising an unhandled `RuntimeError` instead of the expected `WebSocketDisconnect`.
4. **v03.01** — Nothing in the WS contract told a connecting client its own assigned symbol (X/O), so an agent had no way to know whether to act on the very first turn. Added a one-time `joined` event sent right after accept.
5. **v03.02 area, test-only** — A test asserting `os.environ` isolation was actually reading the real `.env` file on disk (via `load_dotenv()`), making it pass/fail depending on ambient state rather than the code under test.
6. **v05.03** — `python client/agent.py ...` — the exact CLI invocation every roadmap issue documents from v03.01 onward — crashed with `No module named 'client'`, since direct script execution doesn't add the project root to `sys.path`. Fixed with a `sys.path` shim gated on `__package__` being empty.

## What was not run live

Per the project's own testing philosophy ("LLM calls are always mocked... never hitting paid external APIs"), no phase of this run made a real call to the Gemini API, even though a real `GEMINI_API_KEY` was present in `.env`. Every LLM-touching test mocks `google.genai.Client`. The v05.03 swarm script was validated structurally (syntax, live match creation, CLI subprocess wiring) but not run end-to-end with two live, billed agents. Separately, no browser-automation tool was available in this environment, so all Web UI (Phase 4) behavior was validated by code review and `node --check`/served-content assertions rather than an actual rendered browser session — both are called out as follow-up spot-checks worth doing manually.
