## Findings

### #1 🟡 Bare traceback on connection failure (LOW) — deferred to v05 polish
If the server isn't running, `asyncio.run(run_agent(...))` propagates a raw
`ConnectionError`/traceback out of `main()`. For a local dev CLI this is acceptable observability, but
a friendly "couldn't reach the server at <url>" line would be nicer. Homed to **v05** (polish & docs)
rather than fixed now — it's ergonomics, not correctness.

## What's solid
The turn-gate is exactly right: `_maybe_move` returns `[]` unless `current_turn == self.symbol`, so the
agent never acts on the terminal `state_update` (whose `current_turn` is `null`) — proven by the
integration test's assertion of **exactly 4** model calls across a full game. `choose_move` treats an
illegal/unparseable/erroring reply as a failed attempt and falls back to `random.choice(valid_moves)`,
so a model failure can never stall the match. The secret flow honors §9: `load_api_key` reads
`ANTHROPIC_API_KEY` in the agent only, and `join_match` sends just `match_id`/`player_name` (never the
key) — the key reaches only the Anthropic SDK. The ws-URL derivation `replace("http", "ws", 1)`
correctly yields `ws://` and `wss://` (and only rewrites the scheme, not a later "http" in a host).
`AgentSession` imports nothing from `server/` and records only the *opponent's* moves/chat (never its
own). Opponent chat still flows through the v02.02 injection guard + length cap. Zero paid calls
anywhere (the LLM is mocked in every test).
