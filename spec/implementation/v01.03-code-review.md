# Code Review & Fix Recommendations — v01.03 (match, seats & lobby REST)

**Date:** 2026-07-21 · **Reviewer:** Claude Opus 4.8, via `/ship-solution`
**Scope:** `server/main.py` (app + lobby REST), `server/auth.py`, `server/schemas.py`, `server/match.py`,
and their tests.
**Method:** manual adversarial read — token validation + cross-match rejection, the join/404 path, the
observer-before-seat ordering, the seat-helper delegation, and input hygiene on the lobby body.

## Recommendation summary

*No findings.* Identity is keyed by token end-to-end, the observer flag is written before any seat can
be assigned, and `validate_token` rejects both unknown and cross-match tokens.

## Findings
None.

## Notes considered and set aside (not findings)

- **`player_name` may be empty** (`JoinRequest.player_name` has no min-length). Not a defect: the name
  is display-only and is **never** an identity key — seats are keyed by the token (§5.2), so a blank or
  duplicate name can't merge or hijack a seat. Enforcing a non-empty name is cosmetic polish, out of
  the v01.03 DoD; if ever wanted it belongs with the v05 hardening pass, not here.
- **A client can `join` a match that is (later) `finished`.** No `status` gate on join. Not in scope:
  match `status`/`result` are first written by the move-authority flow in **v01.04**; until then there
  is no finished state to gate on, and joining a terminal match simply yields an observer-style view of
  the final board. Revisit only if v01.04 wants join to reject finished matches.
- **`create_match` is unauthenticated** — anyone can create matches. Intentional for the local-first
  MVP (§12); not a security gap at this scope.

## What's solid
`validate_token` rejects an unknown token *and* a valid token presented for a different match
(`participant.match_id != match_id`), so a token can't be replayed across matches. The observer flag is
persisted at join **before** any seat exists, so `assign_symbol` (which returns `None` for
`is_spectator`) can never hand an observer a seat — the ordering is enforced by construction, not by a
runtime check that could be skipped. `match.py` is a genuinely thin wrapper — it opens a session and
delegates to the Repository's §5.2 rule, re-implementing nothing, so there is exactly one seat
authority. `JoinRequest` uses `extra="forbid"`, so a typo'd field fails loudly rather than being
silently dropped. `create_app` binds the session maker into `app.state`, so tests' throwaway engine
never leaks into the process-wide default. No secret or model is involved this phase.

## Architecture impact
None — §3/§6.1/§6.3 implemented exactly as documented; the seat-by-token identity contract (§5.2) is
realized against real tokens without changing the seam.
