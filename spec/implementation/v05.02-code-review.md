## Findings

### #1 🟠 Flaky agent-vs-agent driver (MEDIUM, test-only) — FIXED during execution
An earlier draft fed X's `joined` (which makes X move) before receiving O's `joined`. X's move
broadcasts from a different server task than O's connect handler, so the `state_update` could reach
O's socket before its `joined` — the test then read a non-`joined` event and `KeyError`'d (~40% of
runs). **Not a production bug:** `AgentSession.on_event` is order-tolerant (a pre-`joined`
`state_update` finds `mySymbol is None` and simply doesn't act), so a real client is unaffected — this
was a test-driver ordering assumption. **Fix:** receive both `joined` events before feeding the
sessions. Verified 10/10 deterministic; the whole suite stays green.
