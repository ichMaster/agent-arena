## Bug found and fixed mid-issue

`python client/agent.py --match-id ...` — the exact invocation form documented by every roadmap issue since v03.01 — crashed with `ModuleNotFoundError: No module named 'client'`. The module's absolute imports (`client.llm`, `client.memory`, `client.profile`, `client.prompt`, `client.schemas`) only resolve when the project root is on `sys.path`; running the file directly instead puts just its own directory (`client/`) there. Fixed by inserting the project root onto `sys.path` at the top of `client/agent.py`, gated on `__package__` being empty so normal imports (`from client.agent import ...`, used throughout the test suite) are unaffected. Locked in with a real subprocess test (`test_agent_py_runs_as_a_direct_script`) rather than just an import-level check.

## Deliberately not done: a live end-to-end swarm run

Actually running `run_swarm.sh` would spawn two agents making real, billed calls to the Gemini API using the `.env` key recovered earlier this session — the project's own testing philosophy explicitly forbids this even in normal test runs ("LLM calls are always mocked... ensuring tests run instantly and cost nothing"). Validated instead, without spending real API quota:
- Match creation + `match_id` JSON parsing against a real running `uvicorn` server (the exact `curl` + `python3` pipeline the script uses).
- `client/agent.py --help` as a real subprocess (proves the direct-execution fix and full CLI wiring).
- `tests/test_swarm_script.py`: bash syntax (`bash -n`), executable bit, and that the script references the real profile files and the real lobby endpoint.
