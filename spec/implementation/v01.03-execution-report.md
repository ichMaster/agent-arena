## Highlights

- **App gate:** `create_app(db_engine, session_maker)` factory so tests bind a throwaway engine; a
  `lifespan` runs `init_models` on startup (no deprecated hooks); `GET /api/v1/health` and a
  per-request `Repository` dependency. REST stays under `/api/v1/*` — no `/ui` mount or CORS yet (v03).
- **Auth:** `issue_token` = `secrets.token_urlsafe(32)`, the frozen `IssuedToken`, and `validate_token`
  (None for unknown or cross-match). `Repository.get_participant` already existed from v01.02, so no
  Repository change was needed — as the reconcile flagged.
- **Lobby REST:** create returns a uuid `match_id`; join 404s on an unknown match, else issues a token
  and writes the participant with `is_spectator` set *before* any seat.
- **Identity end-to-end:** `match.py` wraps the Repository's §5.2 rule; the identity tests prove two
  distinct tokens get X/O, a third gets none, a spectator is never seated, and — the key rule — two
  joins both named "Human" get **distinct** seats (keyed by token, not name).
