## Findings

### #1 🟡 `no-store` prefix over-match (LOW) — FIX NOW
`server/main.py`'s middleware used `request.url.path.startswith("/ui")`. **Failure scenario:** a future
route like `/uikit` or `/ui-info` (or today, a 404 for `/uixyz`) wrongly receives `Cache-Control:
no-store` — a latent trap that couples unrelated paths to the UI's caching policy. **Fix:** match the
mount exactly — `path == "/ui" or path.startswith("/ui/")`.

### #2 🟡 `error` not surfaced (LOW) — DEFER → v03.03
`routeEvent`'s `error` case only logs to the console. web_ui_spec §6.1 wants a system/error line in
chat — but the system-chat rendering arrives in v03.03. Homed there; the connection is already kept
(the case is a no-op, not a disconnect).

### #3 🟡 X-ghost on hover for O (LOW) — accepted
`.cell.empty.playable:hover::after { content: "X" }` ghosts an X even when the human is O. This is
verbatim from the design source (ui_prototype.html) and is purely cosmetic; the actual mark rendered
on click is always correct. Kept as-is per the committed aesthetic.

`no-store` (under the old prefix match it wrongly carried it).
