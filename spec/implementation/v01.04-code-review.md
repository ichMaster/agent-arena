## FIX NOW

### #1 — `assign_symbol` seat race: the second simultaneous connection crashes  🔴 HIGH
**Where:** `server/repository.py:65-92` (`assign_symbol`) + `server/main.py:142` / `:153`
(`_ws_connection` catches only `WebSocketDisconnect`).

**What happens:** `assign_symbol` reads the taken symbols, then writes the first free one, with no
handling of the `UNIQUE(match_id, symbol)` violation it *relies on*. Two connections that interleave
at the `SELECT`/`commit` awaits both see `taken == {}`, both pick `X`; the second `commit()` raises
`IntegrityError`, which is **not caught** and escapes as an ASGI error — the second client's WebSocket
dies with **no `joined`, no seat**.

**Repro:** two clients (or two agents) open `ws/match/{id}` at the same instant → one crashes instead
of getting seat `O`. Timing-dependent, so the sequential-connect tests never hit it.

**Why now:** this is precisely **v04's** headline path (launch two agents against one match).
`scripts/run_arena.sh` is *specced* to serialize connects to dodge it — i.e. the code is knowingly
not race-safe. Make the UNIQUE constraint do its job instead of relying on external ordering.

**Proposed fix:** in the assign loop, wrap `commit()` in `try/except IntegrityError`; on violation
`await session.rollback()`, re-read `taken`, and retry with the now-remaining symbol (bounded to the
two symbols). Add a regression test that drives two *concurrent* `assign_symbol` calls (e.g. via
`asyncio.gather` on a shared temp-file DB) and asserts they resolve to `{X, O}` with no exception.
Since this touches the §5.2 seat rule, keep the seat contract test green.

### #3 — Observers can post chat (server doesn't enforce read-only)  🟠 MEDIUM
**Where:** `server/main.py:70-76` (the `chat` branch).

**What happens:** `sender = symbol or "observer"` and the message is broadcast — so a spectator
(`symbol is None`) injects chat into the room. Spec §3.3/§3.5: "only players post chat; observers
watch read-only," and "the server is the ultimate authority." The UI suppresses it in v03.03, but the
authority layer should reject it. (Chat is non-authoritative flavor, so this is a rule violation, not
a breach.)

**Proposed fix:** in the `chat` branch, if `symbol is None`, send an `error` ("observers cannot chat")
and return — do not persist or broadcast. Add an integration test: a spectator's `chat` yields an
`error` and no `chat_message` reaches the room.

> Both #1 and #3 are small, well-contained server-side changes with tests. Ship them together as a
> post-release patch **`v01.04.01`** (per the `vXX.YY.ZZ` scheme, `ZZ` is a post-release fix on the
> phase). Bundling the optional **#9** (reject empty `player_name`) here is reasonable.

## Fixes applied (target release `v01.04.01`)

All three FIX-NOW items were implemented in-session, each with a regression test; the full suite is
green (**132 passed**, deterministic) and `mypy --strict` is clean (15 source files). No seam
contract changed, so `spec/architecture.md` was untouched.

### ✅ #1 — race-safe `assign_symbol`  ·  commit `d3609c4`
- **Change:** `server/repository.py` `assign_symbol` now runs in a bounded retry loop — it picks the
  first free symbol, and if the `commit()` raises `IntegrityError` (a concurrent connection took the
  same symbol first), it `rollback`s, re-reads the taken set, and retries with the remaining symbol.
  The `UNIQUE(match_id, symbol)` guard now *resolves* the race instead of crashing on it.
- **Test:** `tests/test_seats.py::test_concurrent_assign_resolves_to_distinct_seats` drives two
  concurrent `assign_symbol` calls on separate sessions via `asyncio.gather` and asserts `{X, O}`
  with no exception. Verified stable across repeated runs.
- **Result:** two clients/agents connecting at the same instant now reliably get distinct seats — the
  v04 two-agent-connect path no longer risks an ASGI crash on the second connection.

### ✅ #3 — observers cannot chat  ·  commit `33e892a`
- **Change:** `server/main.py` chat handler now rejects a seatless (`symbol is None`) connection with
  an `error` ("observers cannot chat") and neither persists nor broadcasts the message — the server
  enforces the "observers watch read-only" rule (§3.3) instead of relying on the UI.
- **Test:** `tests/test_ws_chat.py::test_observer_chat_is_rejected` — a spectator's `chat` yields an
  `error`, no `chat_message` reaches the room, and nothing is persisted.

### ✅ #9 — reject empty `player_name`  ·  commit `33e892a`
- **Change:** `POST /api/v1/lobby/join` returns **400** for an empty/whitespace `player_name`.
- **Test:** `tests/test_lobby.py::test_join_empty_player_name_returns_400` (both `""` and `"   "`).

**Next:** cut the patch with `/release-version 01.04.01` (tag `opus-v01.04.01`).
*(Superseded: #1/#3/#9 shipped inside `opus-v02.01.00` instead of a separate v01 patch.)*

### ✅ #2 — cancellation-safe seat release · HARDEN sweep (`/ship-phase v02 --harden`), commit `ff0f01e`
- **Change:** the WS `finally`-cleanup awaits `release_seat` under `asyncio.shield`, so a
  client-initiated drop (task cancellation, §10) can't interrupt the release mid-commit and leak the
  seat. **Test:** `test_ws_resilience.py::test_dropped_seat_reclaimable_by_another_participant` —
  A drops, B reclaims A's `X`.
- **Architecture impact:** none (implements §10's documented intent; no contract change).
- **v05.01 note:** this addresses v05.01's "release the seat on disconnect / cancellation path" task —
  mark it done when that version is generated.

### ✅ #4 — malformed WS JSON keeps the connection · HARDEN sweep, commit `ff0f01e`
- **Change:** the receive loop parses JSON itself; malformed JSON or a non-object message yields an
  `error` event and the connection stays up (§9's "malformed JSON → error, connection kept").
  **Test:** `test_ws_resilience.py::test_malformed_json_keeps_connection`.
- **Architecture impact:** none. **v05.01 note:** addresses v05.01's malformed-JSON task — mark done.

## DEFER (with homes)

### → v05.01 (Resilience & reconnection — already scheduled)
- **#2 — Seat release on client-drop.** The WS `finally` awaits `release_seat`, but a client-initiated
  drop cancels the task and the awaited release can be interrupted before it commits, so a dropped
  seat leaks and a reconnect can't reclaim it. v05.01's DoD explicitly covers "a dropped seat is
  reclaimable … treat cancellation and `WebSocketDisconnect` alike." (`server/main.py:155-158`)
- **#4 — Malformed WS JSON.** `receive_json()` on non-JSON raises (not `WebSocketDisconnect`) →
  connection torn down. v05.01's DoD: "malformed JSON → `error`, connection kept." (`server/main.py:148`)
- **#10 — `reconstruct_game` ignores `apply_move`'s return** (`server/repository.py:113-114`). Safe today
  (only validated moves are logged); fold a defensive guard into v05.01 hardening.

### → v02.03 (Agent event loop & CLI)
- **#7 — No `.env` loader.** `load_api_key` reads only `os.environ`; the roadmap's "key in `.env`"
  needs a dotenv load at agent startup. Natural home is the agent CLI entrypoint (`agent/agent.py`).

### → Opportunistic cleanup (or `/simplify` on the WS layer)
- **#5 — Triple reconstruction per `submit_move`** (`server/main.py:102-115`; `current_turn` reconstructs
  again at `repository.py:119`, and `_current_state` a third time). Reuse one reconstruction.
- **#6 — `current_turn` counts filled board cells** (`repository.py:122`) — couples to TicTacToe's
  falsy-empty representation. Derive turn from the move-row count instead; revisit when a second game
  module lands.

### → Documented / post-MVP
- **#8 — Seat-bearing token in the URL query** (`server/main.py:130`). Participant IDs can be logged by
  proxies; a leaked token = seat hijack. MVP-accepted per §6.3 (opaque token); revisit (header/subprotocol
  or signed token) after the MVP.
- **#9 — `join` accepts empty `player_name` / no length bound** (`server/main.py:191-202`). Minor input
  hygiene — quick win, optionally bundled into `v01.04.01`.
