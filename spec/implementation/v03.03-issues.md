## v03.03 Tasks

### ARENA-022 — Extract & Parse LLM Structured Output

**Description:**
The Agent currently generates free-form text. We need it to output a structured JSON payload so we can extract both its move (an integer) and its arrogant comment (a string). We can use `google-genai` Structured Outputs (`response_schema`) or simply enforce a strict JSON format in the prompt and parse it.

**What needs to be done:**
- Define a Pydantic schema `AgentResponse` containing `move: int` and `comment: str`.
- Modify `GeminiClient.generate_response` (or add a new method `generate_structured_response`) to force the LLM to output strictly matching this schema.
- Update the prompt in `agent.py` to instruct the LLM to return JSON instead of plain text.
- Add error handling for JSON decode failures.

**Dependencies:** None

**Expected result:**
The LLM response is predictably parsed into a Python object containing `move` and `comment` fields.

**Acceptance criteria:**
- [ ] `GeminiClient` supports returning structured JSON or a Pydantic object.
- [ ] Prompt explicitly instructs the LLM on the required format.
- [ ] LLM output is successfully parsed into a Python dictionary or object.

### ARENA-023 — Valid Move Enforcement & Retry Loop

**Description:**
LLMs hallucinate. If the agent picks a cell that is already occupied or out of bounds (0-8), we must catch it client-side and ask the LLM to try again, providing it with the error message.

**What needs to be done:**
- In `agent.py`, after receiving the parsed `move`, check if it exists in the `valid_moves` array.
- If invalid, construct a follow-up prompt: `"Error: Move X is invalid. The valid moves are Y. Try again."`
- Implement a bounded retry loop (e.g., max 3 attempts) in `agent.py`. If it fails 3 times, pick a random valid move as a fallback to prevent stalling the game.

**Dependencies:** ARENA-022 (#22)

**Expected result:**
The agent is resilient against hallucinated moves and gracefully falls back to a random valid move if it gets stuck.

**Acceptance criteria:**
- [ ] Agent validates the LLM's chosen move against the `valid_moves` list.
- [ ] On failure, it hits the LLM again with an error prompt.
- [ ] After 3 failures, it selects a random valid move.
- [ ] Does not stall the game loop.

### ARENA-024 — WebSocket Submission & Game Loop Completion

**Description:**
With a validated move and an arrogant comment in hand, the Agent must formulate the official JSON payloads and send them to the Game Server over the WebSocket.

**What needs to be done:**
- Send the Agent's comment to the chat using the standard payload: `{"action": "chat", "payload": {"message": "..."}}`.
- Send the Agent's move using the standard payload: `{"action": "submit_move", "payload": {"move": X}}`.
- Ensure `agent.py` correctly awaits the WebSocket sends.

**Dependencies:** ARENA-022 (#22)

**Expected result:**
The Agent plays a full game of Tic-Tac-Toe autonomously against a human opponent. 

**Acceptance criteria:**
- [ ] Agent's comment appears in the server's chat broadcast.
- [ ] Agent's move modifies the game state on the server.
- [ ] Agent can complete a full game (win, lose, or draw) without crashing.
- [ ] Meets Phase DoD: The Agent Client completes a full game of Tic-Tac-Toe autonomously against a dummy opponent.
