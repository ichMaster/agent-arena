## Bug found and fixed mid-issue

The first version of the winning-line test helper interleaved the loser's filler moves *after* the winner's moves, including after the winner's final (winning) move. For 2 of the 8 lines, those filler moves happened to complete an unrelated winning line for the loser using low-numbered cells that get checked earlier in `WINNING_LINES`, so `is_game_over()` reported the wrong winner — correctly, since the board it was given had two simultaneous "winners," which can never happen in a real game (play stops the instant someone wins). Fixed by reordering the helper to always play the winner's third cell last, with no further moves after it — this is not a change to the engine, `games/tictactoe.py` was correct throughout.
