## v02.02 Tasks

### ARENA-014 — Tic-Tac-Toe Engine Logic

**Description:**
Build the concrete implementation of `GameInterface` specifically for Tic-Tac-Toe. It will maintain the internal state of a 3x3 grid and calculate mathematically whether a winning condition has been met or if the board is fully occupied (draw).

**What needs to be done:**
- Create `games/tictactoe.py`.
- Define `TicTacToe` class inheriting from `GameInterface`.
- Store the board internally (e.g., a 1D array of 9 elements containing 'X', 'O', or None).
- Implement `get_state()` to return the board representation.
- Implement `get_valid_moves()` to return indices of all empty cells.
- Implement `apply_move(player, move)` ensuring the target cell is empty and valid before marking the board.
- Implement `is_game_over()` evaluating the 8 possible winning vectors (3 rows, 3 columns, 2 diagonals).

**Dependencies:** None

**Expected result:**
A mathematically sound Tic-Tac-Toe engine decoupled from server networking.

**Acceptance criteria:**
- [ ] `TicTacToe` implements all `@abstractmethod`s from `GameInterface`.
- [ ] `get_valid_moves()` correctly identifies unplayed cells.
- [ ] `apply_move()` rejects out-of-bounds or previously played cells, returning `False`.
- [ ] `is_game_over()` accurately identifies the winning player ('X' or 'O') or a 'draw'.

### ARENA-015 — Unit Tests for Tic-Tac-Toe Engine

**Description:**
Establish extremely rigorous unit tests for the Tic-Tac-Toe engine to ensure edge cases, permutations, and out-of-bounds inputs cannot corrupt the state.

**What needs to be done:**
- Create `tests/test_tictactoe.py`.
- Write tests simulating normal playthroughs.
- Write tests for every single winning permutation (rows, cols, diags for both players).
- Write tests verifying draw scenarios (board full with no winner).
- Write failure tests for out-of-bounds moves (e.g., negative indices, indices > 8) and colliding moves.

**Dependencies:** ARENA-014

**Expected result:**
100% logic coverage for the Tic-Tac-Toe engine, assuring safety before it's wired into the WebSocket endpoints.

**Acceptance criteria:**
- [ ] Pytest comprehensively covers all 8 winning vectors.
- [ ] Pytest verifies the draw condition behaves correctly.
- [ ] `apply_move` rejects invalid input safely.
- [ ] Meets Phase DoD: Highly exhaustive unit tests for every winning permutation, draw states, and out-of-bounds move rejections.
