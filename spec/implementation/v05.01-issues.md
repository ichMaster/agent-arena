## v05.01 — Resilience & reconnection

### ARENA-OPUS-034 — Resilience verification: same-token reconnect reclaim + no-leak tests

**Description:** the resilience code is already in place (see the reconciliation table); this issue
**closes the one coverage gap** — a participant that drops and **reconnects with the same token
reclaims a seat** — and asserts no seat is leaked across a drop/reconnect cycle. Test-only; no
production change. Touches: `tests/`.

**What needs to be done:**
- `tests/test_reconnect.py`:
  - `test_same_token_reconnect_reclaims_seat`: player A joins → WS connect → gets `X`; A drops (WS
    context exit) → the shielded cleanup frees `X`; A **reconnects with the same token** → gets a seat
    again (poll briefly for the shielded release, mirroring the existing resilience test).
  - `test_drop_then_reconnect_leaves_both_seats_usable`: after an A drop + A reconnect, a second
    player B can still take the remaining seat — i.e. exactly two seats exist, none leaked.
- No source change; the LLM is not involved (pure server/WS + DB paths). Confirm the full resilience
  set (existing + new) is green and deterministic.

**Dependencies:** None (verifies the shipped v01.04/v02.03.01 resilience).

**Expected result:** a dropped player reconnecting on the same token reclaims a seat; the two-seat
invariant holds across drop/reconnect — no leak.

**Acceptance criteria:**
- [ ] `test_same_token_reconnect_reclaims_seat` passes (same-token reconnect gets a seat after a drop).
- [ ] `test_drop_then_reconnect_leaves_both_seats_usable` passes (no seat leaked; both seats usable).
- [ ] The whole resilience suite is green and **deterministic** (stable across repeated runs); no LLM, no paid call.
- [ ] mypy (strict) clean (test-only). Ties to DoD: a disconnecting player frees their seat for a reconnect; the server never leaks a seat on a disconnect path.
