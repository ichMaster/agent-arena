## v05.01 — Resilience & reconnection

### ARENA-OPUS-OPUS-034 — Resilience verification + malformed-JSON fix: reconnect reclaim, no-leak, graceful bad input

> **⟳ Reconciled (2026-07-21):** re-scoped from test-only to test **+ one small production fix** — the
> malformed-JSON DoD line was never implemented (see the file intro). Closing it is small and
> self-contained enough to belong in this same checkpoint issue.

**Description:** most of the resilience code is already in place; this issue **closes two gaps**:
(1) test coverage — a participant that drops and **reconnects with the same token reclaims a seat**;
and (2) a real gap — `_ws_connection` currently lets malformed (non-JSON) input crash the connection
instead of sending an `error` and continuing. Touches: `server/main.py`, `tests/`.

**What needs to be done:**
- **Fix (`server/main.py::_ws_connection`):** parse the received frame manually (`receive_text` +
  `json.loads`); on invalid JSON (or a non-dict payload) send the existing `error_event("malformed
  message")` and `continue` the loop — never crash it, never drop the connection. Reuses the shipped
  `error_event` shape; no new wire contract.
- `tests/test_reconnect.py`:
  - `test_same_token_reconnect_reclaims_seat`: A joins → WS connect → `X`; A drops → the shielded
    cleanup frees `X`; A **reconnects with the same token** → gets a seat again.
  - `test_drop_then_reconnect_leaves_both_seats_usable`: after A drops + reconnects, a fresh player B
    can still take the remaining seat — exactly two seats, none leaked.
  - `test_malformed_json_keeps_connection`: send non-JSON text over an open WS; assert an `error` comes
    back (not a raised exception / dropped connection) and the socket still accepts a normal action.
- The LLM is not involved (pure server/WS + DB paths). Confirm the full resilience set is green and
  deterministic.

**Dependencies:** None. **Expected result:** a dropped player reconnecting on the same token reclaims a
seat; the two-seat invariant holds across drop/reconnect; malformed input no longer crashes a connection.

**Acceptance criteria:**
- [ ] `test_same_token_reconnect_reclaims_seat` passes (same-token reconnect gets a seat after a drop).
- [ ] `test_drop_then_reconnect_leaves_both_seats_usable` passes (no seat leaked; both seats usable).
- [ ] `test_malformed_json_keeps_connection` passes: invalid JSON yields an `error`, connection stays open + usable.
- [ ] The whole resilience suite is green and **deterministic**; no LLM, no paid call.
- [ ] mypy (strict) clean. Ties to DoD: a disconnecting player frees their seat for a reconnect; a malformed message is rejected without killing the socket; the server never leaks a seat on a disconnect path.
