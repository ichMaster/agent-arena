# Agent Arena — Release Notes

## v05.01.00 — Designer Schemas
- `client/profile.py`: `AgentProfile` Pydantic schema (`name`, `model_type`, `temperature`, `system_prompt`, `memory_limit`) with `load_from_yaml`.
- `profiles/aggressive_bot.yml` and `profiles/cowardly_bot.yml` — two distinct sample personas.

## v04.03.00 — Reactive DOM & Chat
- `renderBoard` writes each cell's mark/glow class and toggles player-card `.active` state from `current_turn` vs the locally-learned `mySymbol`; cells are only clickable when it's genuinely this client's turn on an empty, valid cell. `handleCellClick` sends `submit_move`.
- `renderChat`/`addMessage` append styled, safely-escaped chat bubbles (system/user/agent) via DOM methods, not `innerHTML`. Chat input enables on connect. `handleGameOver` freezes the board and surfaces the win/draw result.
- **Phase 4 DoD met: a human player can play a full game of Tic-Tac-Toe against the Agent entirely through the Web UI** (per code review; no browser-automation tool available in this environment for a live drive-through).

## v04.02.00 — Native WebSockets & Authentication
- `web/app.js`: `hostMatch()`/`joinExistingMatch()` hit the lobby HTTP endpoints and acquire an auth token; `connectSocket()` then opens a real `WebSocket` to `/ws/match/{id}?token=...`.
- Server Status dot toggles green/red on `onopen`/`onclose`; `onmessage` routes every real event type (`joined`, `state_update`, `chat_message`, `game_over`, `error`) through a dispatcher — DOM rendering from these lands in v04.03.

## v04.01.00 — HTML/CSS Skeleton
- `web/index.html` + `web/styles.css`: semantic structure split out from `spec/ui_prototype.html`, no JS yet — buttons/inputs present but inert.
- Full Glassmorphism color system as CSS custom properties (accent/agent/status colors, glass-inset opacities), 3x3 CSS Grid board, Flexbox chat sidebar, and a responsive breakpoint (the prototype had none) so the layout stacks and fits on narrow viewports.
- `/ui` mounted as static files on the FastAPI app so the frontend is actually reachable.

## v03.03.00 — Tool Calling & Parsing
- `client/schemas.py`: `AgentResponse` (`move`, `comment`); `GeminiClient.generate_structured_response` forces the SDK to return JSON matching it.
- `AgentSession._decide_move`: validates the move against `valid_moves`, retries up to 3 times with an explicit error prompt on rejection or unparseable output, then falls back to a random legal move — never stalls the game.
- `on_my_turn` now transmits the decided move back to the server (`chat` with the taunt, then `submit_move`), closing the loop.
- Verified against a real `uvicorn` server: the agent autonomously joins, decides, and plays — no manual driving. **Phase 3 DoD met: the Agent Client completes a full game of Tic-Tac-Toe autonomously.**

## v03.02.00 — LLM Seam & Persona
- `client/llm.py`: `LLMClient` abstract seam + `GeminiClient` wrapping `google-genai`'s async client, hardcoded to `gemini-3.1-pro`. Fully mocked in tests — never hits the real paid API.
- `client/memory.py` / `client/prompt.py`: `MemoryWindow` (rolling buffer of recent chat/moves) and `build_prompt` combining the hardcoded persona + memory + board + valid moves.
- `AgentSession` now builds a prompt and calls the LLM on its own turn, logging the raw response (translating it into an actual move is v03.03).

## v03.01.00 — Agent CLI Skeleton & WebSocket Loop
- `client/agent.py`: CLI (`--match-id`, `--server-url`, `--player-name`) that loads `.env` (fails fast if `GEMINI_API_KEY` is missing), joins the lobby over HTTP, and runs a real-time `AgentSession` event loop over `websockets`.
- New WS protocol event: server sends a one-time `joined` event (assigned symbol + board/turn) right after every connection accepts, so a client can know whose turn it is before ever moving — symbol assignment moved from first-move time to connect time.
- Verified against a real `uvicorn` server (not just the ASGI test transport): two agent sessions connect, learn X/O, and play a full game to `game_over` over an actual socket.

## v02.03.00 — Match Orchestrator & WS Integration
- `server/match.py`: `Match` holds a live `TicTacToe` instance and lazily assigns X/O symbols to the first two distinct player names to act.
- WS router handles `submit_move`: valid moves persist + broadcast `state_update`; invalid/out-of-turn/third-player moves get an isolated `error`; a completed game broadcasts `game_over` and gracefully closes every connection in the room.
- 2 real WebSocket clients play a full game end-to-end through `/ws/match/{match_id}` (Phase 2 DoD).

## v02.02.00 — Tic-Tac-Toe Engine
- `games/tictactoe.py`: concrete `TicTacToe(GameInterface)` — 3x3 board, all 8 winning vectors, draw detection, rejects occupied/out-of-bounds/non-integer moves.
- 25 exhaustive tests covering every winning permutation for both players plus edge cases.

## v02.01.00 — Game Interface
- `games/interface.py`: abstract `GameInterface` (`get_state`, `get_valid_moves`, `apply_move`, `is_game_over`), fully decoupled from FastAPI/WebSocket/DB — cannot be instantiated directly.
- `mypy.ini` enforces strict typing on `games/*`; `requirements-dev.txt` adds `mypy` for local/CI checks.

## v01.03.00 — WebSocket Connection Manager
- `ClientActionPayload`/`ServerPushEvent` Pydantic schemas and a `ConnectionManager` singleton (`match_id -> [WebSocket]`).
- `POST /lobby/join` now issues real, validated tokens (in-memory store keyed by `match_id`); `/ws/match/{match_id}` accepts only a correct token for that specific match, closing pre-`accept()` (code 4001) otherwise.
- `/lobby/match` now persists a `MatchModel` row so later chat/move FK constraints resolve correctly.
- WS receive loop validates `chat` actions, persists them via the `Repository`, and broadcasts to the room; malformed JSON or unknown actions get an isolated `error` reply without dropping the connection.
- Replaced the deprecated `@app.on_event("startup")` with a `lifespan` context manager.
- 2+ concurrent WebSocket clients verified to exchange chat within a match and never cross-talk between matches.

## v01.02.00 — Database Layer
- Async SQLAlchemy engine over `aiosqlite` (`sqlite+aiosqlite:///arena.db`) with SQLite foreign-key enforcement enabled.
- `MatchModel`, `MoveLogModel`, `ChatLogModel` schema with FK relationships.
- `Repository` class abstracting CRUD for matches, moves, and chat logs behind async, type-hinted methods.
- `server/init_db.py` verification script; FK violations are proven to raise `IntegrityError`.

## v01.01.00 — Server Skeleton & Lobby
- FastAPI app instance with CORS middleware for local development.
- `GET /api/v1/health` liveness probe.
- `POST /api/v1/lobby/match` — generates a UUID4 `match_id`.
- `POST /api/v1/lobby/join` — accepts `match_id`/`player_name`, returns an opaque auth token.
